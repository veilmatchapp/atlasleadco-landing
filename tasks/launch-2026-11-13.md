# Launch, 2026-11-13

The new site went live at https://www.atlasleadco.com/ (Vercel production deployment from commit `38f23b4`).

## What is served
Vercel serves the committed `public/` folder as plain static files (`vercel.json`: no install or build step, trailing slashes, security headers). Rebuild it with `npm run build` (builds the pages and assembles `public/`), commit, push; the push deploys.

## The old site is backed up three ways
1. `backup/old-site-2026-11-13/` in this repo: `index.html`, `atlas-logo.png`, and `live-snapshot-www.html` (what www served just before launch, byte-identical to `index.html`).
2. The annotated git tag `old-site-2026-11-13` (on GitHub), pointing at the last commit where the repo root was the old site.
3. Vercel's previous production deployment `atlasleadco-landing-3tqgsnr4k-veilmatch.vercel.app`.

## Roll back
- Fastest: `vercel rollback https://atlasleadco-landing-3tqgsnr4k-veilmatch.vercel.app` (or promote it in the Vercel dashboard). That restores the old site immediately.
- From git: `git checkout old-site-2026-11-13 -- index.html atlas-logo.png`, remove `vercel.json`'s `outputDirectory`, and push.

## Checked after launch
Every page and asset returns 200 on www; the new title is serving; the old lead-gen content is gone; `/security` redirects to `/security/`; the security headers are present; in a real browser the globe loads with no console errors or failed requests; the firewall service shows Join the waitlist.

The DNS is hosted at `ns1.hosting.businessidentity.llc`; add the record `A  atlasleadco.com  76.76.21.21` there (Vercel's recommendation). After that, set the apex to redirect to www in the Vercel domain settings.
